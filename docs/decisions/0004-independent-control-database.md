# 0004. 계정·감사용 control DB 를 대상과 분리

## 맥락
계정·세션·감사가 관리 대상 DB 와 같은 연결 설정을 쓰면, 대상이 내려가거나 설정이 틀렸을 때 로그인조차 못 한다. 여러 환경(시험·운영)을 한 콘솔에서 다루려면 환경마다 연결 값을 따로 둬야 한다.

## 선택지
1. 대상 DB 하나에 모두 둔다(단일 호스트).
2. control DB 를 따로 두고 대상은 환경별 읽기 전용 풀로 연다(중앙).
3. 환경마다 콘솔을 따로 띄운다.

## 결정
두 모드를 함께 둔다. `ADMIN_CONTROL_DATABASE_URL` 을 주면 중앙 모드로, 모든 대상을 `ADMIN_TARGETS` 에 명시하고 대상 설정은 control 의 비밀을 물려받지 않는다. 주지 않으면 단일 호스트 모드로, 빠른 시작에 쓴다. 인증·운영자 관리·준비 상태는 늘 control 만 쓴다({{commit:350593d}}, {{commit:2eb14ff}}).

## 결과
- 대상 장애 중에도 로그인·감사·로그아웃이 된다(`scripts/verify-control-isolation.py`).
- 중앙 모드는 마이그레이션 역할과 런타임 역할을 나눠, 서빙 프로세스는 DDL 비밀을 받지 않는다.
- 설정이 하나 더 복잡해졌다. 대상 키는 환경변수 이름과 같다.
